## 一、产品概述

### 1.1 产品定位

一个基于 DeepSeek 大模型的全栈 AI 聊天助手，支持流式对话、文件解析、本地 OCR 与多会话管理。

**定位声明（诚实版）**：本项目不与 ChatGPT、Kimi、豆包等巨头产品正面竞争通用聊天赛道。它的核心价值有二：
1. **对用户**：提供一个可本地部署、数据自主、零云依赖的轻量 AI 聊天工具，适合对隐私敏感或想自托管的学习者/开发者使用。
2. **对作者**：作为端到端的全栈工程训练项目，验证从流式通信、文件解析、鉴权、持久化到产品交互细节的完整交付能力。

### 1.2 背景与动机

- 通用 AI 聊天赛道已红海化，巨头产品功能完整、免费且体验成熟，个人项目在该维度无差异化空间。
- 市面上的 AI 聊天教程多为 demo 级，缺少对真实工程细节（流式中断清理、附件按需注入、危险操作防误触、移动端适配）的处理。
- 本项目以"把简单事做对"为目标，而非"堆叠新功能"。

### 1.3 目标用户

| 用户画像 | 核心诉求 | 本项目匹配度 |
|:---|:---|:---|
| 自托管爱好者 | 数据不上云、可私有部署、API Key 自管 | 高（本地存储 + 本地 OCR + 自配 Key） |
| 全栈学习者 | 阅读可运行的真实项目代码 | 高（前后端完整、技术栈主流） |
| 隐私敏感用户 | 图片/文档不经过第三方云 OCR | 中高（OCR 完全本地化） |

### 1.4 价值主张

- **数据自主**：对话与文件解析内容仅存本地 `db.json`，不经过第三方云存储。
- **隐私优先**：OCR 使用 Tesseract.js 纯前端识别，图片永不上传服务器。
- **成本可控**：附件内容按需注入上下文，避免每轮重复发送整篇文档造成 Token 浪费。

## 二、竞品简析


| 维度 | ChatGPT / Kimi / 豆包 | 本项目 |
|:---|:---|:---|
| 模型能力 | 顶级大模型，多模态、Agent、插件生态 | 单一 DeepSeek 模型，无 Agent |
| 持久化记忆 | ChatGPT Memory / Custom GPTs / Projects | 仅单会话内上下文，无跨会话记忆 |
| 主动提醒 | ChatGPT Scheduled Tasks 定时任务 | 无 |
| 预设工作流 | Custom GPTs 可固化 prompt 模板 | 无 |
| 文件解析 | 全格式、高精度、多模态理解 | 基础文本提取，无多模态理解 |
| 数据自主权 | 数据上云，受平台政策约束 | **完全本地，用户自管** |
| 部署方式 | SaaS，无法自托管 | **可本地部署** |
| API Key 成本 | 平台承担或订阅制 | **用户自管，按需付费** |

**结论**：在模型能力与产品成熟度上本项目无法与巨头竞争；差异化仅存在于"数据自主 / 可自托管 / 本地 OCR"三个工程属性上。

## 三、用户场景

### 场景 1：本地文档问答
用户有一份本地 PDF 研报，希望在不把文档上传到任何云服务的前提下，让 AI 帮忙总结要点。
- 上传 PDF → 后端提取文本 → 按需注入上下文 → 流式输出总结。

### 场景 2：截图文字识别
用户有一张包含中英文混合文字的截图，希望快速识别成文本并继续追问。
- 上传图片 → 前端 Tesseract.js 本地 OCR → 识别结果作为消息内容发送 → AI 解答。

### 场景 3：多主题并行研究
用户同时研究 3 个不同主题，希望上下文互不干扰。
- 创建 3 个会话 → 各自独立上下文 → 侧边栏快速切换。

## 六、已知局限与迭代方向


| 层面 | 当前实现 | 已知风险 | 迭代方向 |
|:---|:---|:---|:---|
| 数据存储 | JSON 单文件整体覆盖写 | 并发写入丢数据；崩溃可能损坏全库 | 迁移 SQLite + 事务 |
| 用量控制 | 无 rate limit | API Key 可被无限调用，成本失控 | Redis 计数器 + 日配额 |
| 账号体系 | 用户名+密码，邮箱未验证 | 注册门槛高，邮箱无法找回密码 | OAuth + 游客模式 |
| 会话管理 | 仅列表+重命名/删除 | 会话多后无法检索 | 关键词搜索 + 分组 |
| OCR 准确率 | Tesseract.js 本地识别 | 复杂版式/手写体识别率有限 | 可选云 OCR 开关 |
| 安全默认值 | JWT_SECRET 内置默认值 | 不改即为裸奔 | 启动检测默认值并告警 |
| 测试与 CI | 零测试覆盖 | 重构即冒险 | 核心链路单测 |

## 九、附录

### 9.1 技术栈
- 前端：Vue 3 (Composition API) + Vite 5
- 后端：Node.js + Express
- 模型：DeepSeek API (V4 Pro/Flash)
- 鉴权：JWT + bcryptjs
- 渲染：marked + highlight.js
- OCR：Tesseract.js
- 文件解析：pdf-parse / mammoth / xlsx / docx
- 存储：JSON 文件（规划迁移 SQLite）

### 9.2 仓库结构
```
chatbot/
├── client/               # Vue 3 前端
│   └── src/
│       ├── components/   # Chat / ChatInput / ChatMessage / SessionList / Login / SettingsPanel
│       ├── composables/  # useChat（流式对话核心逻辑）
│       └── utils/        # markdown / ocr
├── server/               # Express 后端
│   └── index.js          # 路由 / 鉴权 / 文件解析 / SSE 代理
├── docs/                 # 文档
│   └── PRD.md            # 本文档
└── README.md
```
